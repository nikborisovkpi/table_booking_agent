## Пункт 4. Короткі нотатки (інструменти, що розглядались, фінальний вибір та роль AI)

1. **Telegram-інтеграція:** розглядав стандартний Bot API (`aiogram`) проти MTProto (`Telethon` / `Pyrogram`). Вибрав **Telethon (Userbot)**, оскільки звичайні боти в Telegram технічно не можуть першими ініціювати діалог із користувачем `@vlad_dev_7`.
2. **Оркестрація агента:** розглядав `LangGraph` / `PydanticAI` проти власного легкого tool-calling циклу поверх `AsyncOpenAI` SDK + `Pydantic v2`. Обрав власний цикл без важких фреймворків — це дало повний контроль над ескалацією питань власнику (`ask_owner`), автокорекцією фінальної відповіді (обов'язкова перевірка наявності назви ресторану, дати, часу й кількості гостей) та суворим однорядковим логуванням.
3. **LLM (через OpenRouter):** обрав **`anthropic/claude-haiku-5.5`** за швидкість, низьку вартість і природну британську англійську в діалогах.
4. **Голосовий пайплайн (задача із зірочкою):** оскільки `claude-haiku-5.5` не приймає сире аудіо на вхід, для **STT** під тим самим ключем OpenRouter використав мультимодальну модель сімейства **Gemini Flash** (після нормалізації `.ogg → 16kHz .wav` через `ffmpeg`), а для **TTS** розглядав платні ElevenLabs / OpenAI Audio, але обрав безкоштовний **`edge-tts` (`en-GB-RyanNeural`) + `ffmpeg (libopus)`**, що генерує натуральний британський акцент і нативні Telegram `voice_note` з хвилею звуку.
5. **Використання AI під час розробки:** використовував AI-асистента в режимі архітектурного планування та TDD-розробки — для аналізу прихованих вимог ТЗ (уточнення назви ресторану, робота та самотестування з одного Telegram-акаунта через `Saved Messages` + приватну групу), написання 23 автотестів і відлову конкурентних багів до бойового запуску.

## Пункт 5. Що зламалось у процесі та в чому залишаються сумніви (1 абзац)

Під час розробки й перевірки спливли три реальні технічні проблеми: по-перше, `anthropic/claude-haiku-5.5` в OpenRouter підтримує лише текст і зображення без `input_audio`, тому розпізнавання голосових довелося винести на окрему мультимодальну Gemini Flash модель за тим самим API-ключем; по-друге, автотести виявили стан гонитви в `MessageBatcher`, коли нове повідомлення від менеджера, надіслане під час очікування відповіді власника в `Saved Messages`, зависало в буфері без повторного циклу очищення; по-третє, перший запуск на Windows впав із `UnicodeEncodeError` через системне кодування консолі `cp1251`, що було виправлено примусовим перемиканням потоків у `UTF-8` та додаванням запобіжника від випадкового старту по `@vlad_dev_7` у режимі самотестування. Найбільше невпевненості залишається у поведінці живого співрозмовника на нестандартних медіа та таймінгах: якщо менеджер надішле фото меню чи геолокацію замість тексту/голосу, або робитиме паузи між частинами однієї думки довші за 6-секундне вікно дебаунсу (без індикатора `typing`), агент може відповісти раніше, ніж менеджер допише останнє речення, а при використанні одного Telegram-акаунта для `Saved Messages` власнику потрібно тримати чат відкритим, бо Telegram не шле звукових push-сповіщень на повідомлення самому собі.
